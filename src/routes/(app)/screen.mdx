# Account shell

The shell frames every account page with the Agora navigation rail: the platform's destinations, the
Agora apps and the account controls, and the authentication dialogs. Each preview holds one state
fixed, so dismissing a dialog or a menu leaves it as it was.

The expanded rail shows the Agora wordmark, and the collapsed rail shows its icon, with every
destination and account control named for assistive technology. On mobile, a header keeps the
wordmark and the menu control, and the menu holds the same navigation. "Log in" and "Register" open
their dialogs in place, from the rail or the menu.

Dialog titles and fields share a leading edge. UIKit owns the header controls and the action spacing. Service errors sit above the submit button, which
stays apart from the fields. Mobile actions stack at full width. Desktop actions keep their natural
width, with secondary actions at the end of the footer. Completion states drop the footer.

A request explains the next step before submission. Once the request is recorded or sent, the dialog
heading becomes the outcome, with one compact status message and the submitted address below it.

Validation previews use the same API schemas as the controllers. Invalid credentials read apart from
service outages, which share a short heading and recovery guidance across forms. A successful login
redirects. Invitation requests acknowledge list membership, with distinct warnings for existing
accounts and repeated requests. Recovery acknowledges delivery without disclosing whether an account
exists.
